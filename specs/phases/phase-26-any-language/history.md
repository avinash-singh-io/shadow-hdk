### [DECISION] 2026-09-12 — D67: the thread, the handles, the store and the composition cross the wire; a thread's offer is held by one task

Topics: wire, thread, approvals, store, serve, composition, any-language
Affects-phases: phase-26-any-language
Affects-specs: architecture/wire.md, planning/the-substrate.md#3.8

**The shape.** The wire's first shape (`run`/`resume`, Phase 9) inverts the ports — the host keeps
judge, components and sink, and the runtime calls back — which is right for a host that *is* the
harness. A host in another language wants the other shape: the ports **runtime-side**, composed
by the process serving the wire, and the host driving threads by method. So the runtime side
takes a `ThreadHost` (a port: how to open and resume a thread, and the handles a host answers
through — `approvals`, `store`, `rules`, `modes`), and `ThreadMethods` serves `thread/*`,
`turn/*`, `approvals/*`, `run/cancel`, `store/*`, `modes/list`, `rules/list` on the peer. Events,
items and activity cross as notifications tagged with the thread id (one fold, runtime-side —
D46); the turn's record is the result of `turn/start`. Requests are *pushed* as they become
pending (`approval_request`, `input_request`) and withdrawn (`request_withdrawn`), so a client
need not poll; `approvals/pending` and `approvals/answer` are there for the one that does. The
parity invariant grew rule 4: every public method of `Thread`, `Approvals` and `Store` crosses
under a `protocol.py` name or says why in `HANDLES_NOT_CROSSING`.

**The composition is the harness's.** What the coder and the studio each carried — one
environment with a mode, the shipped skills, `ask_person`, the mode registry over files and a
store, the act rules, the registry offered over the authenticated socket, a provider — is one
package now: `shadow-hdk-serve` (`ServeHost` implements `ThreadHost`; `a_thread` is the
Python-side door onto the same object; `shadow-hdk serve harness.toml --stdio|--http`). The
wire package still imports no adapter: the composition is handed in, not known.

**A thread's offer is held by one task.** Found behind `--http`: the offer's `serve_over_socket`
is an anyio cancel scope, and `Thread.open` entered it in the request task that called
`thread/start` while `Thread.close` left it from the task that called `thread/close` — "exit a
cancel scope that isn't the current task's". So the thread runs its offer in a task of its own
for its lifetime (`_holder`; `_let_go` ends it), and every method may be called from any task.
Loopback never showed it, because there one task did everything.

*Why:* principle 7 — a host holds handles, not code, and every handle crosses the wire; and 8 —
the harness is generic, so the composition a product wants by default is the harness's to ship,
behind one door in-process and one over the wire.

### [DECISION] 2026-09-12 — D68: the TypeScript types are generated by json-schema-to-typescript, one module per contract, held by an invariant

Topics: typescript, schemas, generation, client, invariant
Affects-phases: phase-26-any-language
Affects-specs: architecture/wire.md#schemas, planning/the-substrate.md#3.8

**The survey.** `json-schema-to-typescript` (3.3k stars, Node ≥ 22, draft-07/2019-09 well
covered, 2020-12 partial): emits plain `interface`/`type` declarations, `oneOf`/`anyOf` as plain
unions — which TypeScript narrows on our `kind` literals with nothing lost — and a `--imports`
mode that is still experimental; it does not know OpenAPI's `discriminator` keyword and refuses a
bare root `$ref`. `quicktype` (13.9k stars, Node ≥ 20): many inputs and targets, emits runtime
converters unless `--just-types`, and its schema-draft coverage is undocumented. **Chosen:
json-schema-to-typescript** — types only, which is all a client needs of the contract, and the
smaller thing to keep in step with. Two honest transforms sit in front of it in `generate.mjs`:
`discriminator` is stripped (pydantic writes it beside `oneOf`; it is OpenAPI's, not JSON
Schema's), and a recursive contract published as `{ $defs, $ref }` (`Item`, whose children are
items) is inlined at the root with its self-references rewritten to `#`. **One module per
contract** (`src/schemas/<Contract>.ts`, `src/schemas.ts` the barrel), because contracts share
definitions and one file would declare `Completed` three times. The generator is deterministic
(the contracts in `index.json` order, Prettier off, no timestamps) and takes its paths from the
environment, so the invariant regenerates into a temp directory with the same code path and
diffs — measured to catch a one-line perturbation. The client (`src/client.ts`) is hand-written:
the thread, turn, approval, store and mode methods over `POST /rpc` and an SSE `GET /rpc`, the session id in `x-shadow-hdk-session`,
`turn.start` an async iterator of events, items and activity until the turn's record. It is
proven against a live `serve --http` by the Python suite (`tests/serve/test_the_typescript_client_talks_to_serve.py`)
— a thread started, turned, items and activity seen, the store read — and type-checked by
`tsc --noEmit`. Installed locally under `clients/typescript/node_modules` only; CI installs node
and builds it so the check runs rather than skips. Private, not published.

*Why:* the schemas are the contract (D21); a host in another language must compile against
exactly them, and a generator the build holds to the schemas is how that stays true.

### [DECISION] 2026-09-12 — D69: the studio is a page `serve` itself serves; a session's threads close with it

Topics: studio, serve, page, files, session, any-language
Affects-phases: phase-26-any-language
Affects-specs: architecture/wire.md, planning/the-substrate.md#3.8

The studio used to be a Python host with routes of its own (`/say`, `/stream`, `/answer`,
`/files`) over a `Thread` — a second, local vocabulary beside the wire's. It is now a page
`shadow-hdk serve --http --page examples/studio/page.html` serves at `/`, and the page
talks JSON-RPC over `POST /rpc` and SSE from `GET /rpc` with the methods the TypeScript client
speaks: `thread/start` at load (`thread/resume` when `?thread=` names one — a reload is a new
session resuming the same thread, its turns replayed from the record), `turn/start` per message
(the turn's record is the result; events, items and activity are the notifications between),
`approvals/answer` with the industry's three answers or `{text}`, `thread/set_mode`,
`modes/list`, `store/put` for the admin panel, `rules/list`. The studio's own `__main__` is
`serve` with the page and the flags it always took; `app.py` is gone. Held by a test that reads
the page's source: every method it calls is a name `protocol.py` publishes, and nothing local
remains.

**Two things the wire lacked, found by moving the page onto it.** *Files:* a page shows the
workspace beside the conversation, so `files/list` and `files/read` are thread methods — under
the thread's root only, dotfiles and caches left out, a path that resolves outside refused with
the reason — rather than a route on the side. *Sessions:* a session that ends (the page
reloaded, the pipe closed) now closes every thread it opened (`ThreadMethods.close_all`, shielded,
in the SSE response's `finally` and after `serve_stdio`); measured, without it every reload of
the studio left the previous provider process and its offered socket alive. `thread/start` and
`thread/resume` return the root too, since the page shows it and the client needs it to read.

**The flags.** `serve` takes `--root`, `--mode`, `--store`, `--provider` over the `harness.toml`
(a flag overrides the file), so a launcher need not write a file to name a workspace.

*Why:* the studio is the proof; a proof that spoke a private vocabulary proved a private host,
not the wire. Now what the page does, a product in any language does the same way.
