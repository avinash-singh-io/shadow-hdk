- **2026-10-03 — `0.44.1`: a restricted database role can open the PostgreSQL adapters** (BUG-237,
  Intent Studio's BUG-280, blocking their 0.7.0). A quick-task from the v0.44.0 tag, carrying nothing
  from 0.45.x. The adapters executed their table DDL when a pool first opened **and again after every
  `aclose()`**, so a production runtime role with no DDL rights failed with SQLSTATE 42501.
  Provisioning in advance did not help, and that decides the shape: `CREATE TABLE IF NOT EXISTS` is
  **not** DDL-free, because PostgreSQL checks the CREATE privilege before the existence check — now
  held against a real server by a test rather than asserted. `prepare(url)` plus a
  `shadow-hdk-prepare` console script create every table and call LangGraph's own `setup()` under an
  owner role, idempotently, recording the version in a new one-row table without which *migrates* and
  *behind* would be claims with nothing behind them. `prepared=True` issues no DDL and verifies with
  one catalogue query, failing named at startup; `runtime_grants(role)` publishes the restricted
  role's grants as data, with SELECT only on the version table, and the test grants exactly what it
  publishes. Opt-in here so a patch inverts nothing; the default flips in the first 0.45 release.
  **Three things went wrong on the way and are recorded in the ad-hoc record:** the `prepared` flag
  was accepted and ignored for a while with nine tests green — BUG-230's exact shape inside the fix
  for a different bug, caught by noticing the missing branch rather than by the suite; a killed
  mutation run left `if False:` in the source, which `git diff` caught; and the test itself had
  TD-019's shape, leaving pools open on failure so teardown hung instead of reporting. A line-reflow
  helper that corrupted source twice was **removed from the repository**. Gate: 2167 passed, 8
  skipped (down from 20 — the PostgreSQL suites now run), mypy strict 509 files; five mutations bite.
