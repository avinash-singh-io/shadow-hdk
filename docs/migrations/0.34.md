# Migrating from 0.33 to 0.34

Phase 45 — *truth both ways*. The kit tells a host the truth about its provider — what a turn
really cost, why it really failed, that a second CLI honours the behaviour a mode asked for — and
a host tells the kit its truth per turn. The protocol stays at `3`; every addition is a field, a
parameter or a kind. Three things a host may notice as a change of behaviour are listed at the
end.

## What a turn really cost (ENH-023, D141)

- `Usage` gains `cache_read_tokens` and `cache_write_tokens`; `Spent` gains the same two,
  summed across the thread's turns. `None` on `Usage` where the provider does not report them —
  unknown, never zero; `unmetered` on `Spent` still means a call reported no tokens at all.
- Where they come from: Claude Code's `cache_read_input_tokens` / `cache_creation_input_tokens`
  (its `input_tokens` is the *fresh* part — measured, a turn with `input_tokens=2` read 531 from
  the cache and wrote 2,458); Codex's `cached_input_tokens` / `cache_write_input_tokens` (its
  `input_tokens` *includes* the cached part — 12,032 of 17,393 in one measured turn); LangChain's
  `usage_metadata.input_token_details.cache_read` / `cache_creation`. Each is named in the
  provider file (`Dialect.cache_read_tokens_at`, `cache_write_tokens_at`) or the adapter — never
  in the runtime.
- Records and checkpoints written before 0.34 load with zeros for the two counters.

## Why a turn really failed (ENH-024, D139)

- `TurnRecord.failure` — `""` or `"session_gone"`: the provider no longer has the session the
  thread resumed on. The vocabulary grows by measured kinds only.
- In process, `Thread.turn` raises `SessionGone(thread_id, session_id, provider)` once the
  stream has ended (the record is already written); over the wire `turn/start` answers
  `error.data.kind = "session_gone"` with `thread_id` and `session_id`; the TypeScript client's
  `RemoteError.kind` and `TurnRecord.failure` are typed. The next move is `thread/fork`.
- `Turn.session_gone` for a provider adapter; `Dialect.session_gone_matches` for a provider file
  — substrings of the failure text or the CLI's stderr. Shipped: Claude Code
  (`errors: ["No conversation found with session ID: …"]`, `failed_text_at = "errors"` — a list,
  joined) and Codex (`no rollout found for thread id …`, on stderr). Measured 2026-09-20 on both.
- **A provider's failed turn is now `failed`** (BUG-060). Until 0.34 the runtime read nothing of
  `Turn.failed`: a Codex usage-limit `turn.failed` or a Claude Code `is_error: true` landed on
  the record as a `completed` turn whose text happened to be the error. A host that matched on
  the text will find `outcome == "failed"` and the same text.
- **The JSONL session reads the CLI's stderr** (BUG-059): the last 64 KB are on
  `session.stderr`; a CLI that floods stderr no longer blocks on a full pipe.

## A second CLI's behaviour (ENH-028)

- `codex.toml` maps `model` (`-m <model>`) and `effort` (`-c model_reasoning_effort="<v>"`);
  `unmapped_behaviour` on Codex now names only `system`, `append_system`, `temperature`.
  Measured live on Codex 0.154.0.
- `BehaviourArg.template` — `"key={value}"` — for any CLI whose flag takes `key=value`; a provider
  file's mapping without `{value}` in its template is refused at load.

## A host's words per turn (ENH-037, D140)

- `Thread.turn(text, attributes=…)` / `Conversation.turn(…, attributes=…)` and `turn/start
  {attributes}`: this turn's words, merged over the record's for this turn's judgements — the
  catalogue, the turn's step, every tool call — and never written back.
- `Thread.resume(…, attributes=…)` and `thread/resume {attributes}`: the host's current words
  **replace** the record's, saved, so the trail shows when they changed. Omit to keep the record's.
- The TypeScript client: `turn.start(id, text, { attributes })`, `thread.resume(id, { attributes })`.

## A web read under the shipped modes (ENH-038, D138)

- The `ask` policy's ceiling is uncontained with its ask line contained: an uncontained reach —
  a battery that reads the web from the serving process, `contained = false` — is **asked**
  before, not refused. "Every write, run or delete inside the workspace is asked about" is the
  mode's definition, and Claude Code's default prompts before a fetch the same way. A row
  `component = "web_search", decision = "allow", mode = "ask"` then stands in for the person.
- `read-only` allows it, as its documented definition says (look, and look at the web);
  `workspace-write` hides it; `full` allows it. Nothing changed there.
- Nothing re-vouches a battery's effects: the `ddgs` file's `contained = false` is true and
  stays. A read that *is* contained — through a proxy with an allowlist (D137) — narrows every
  ceiling and needs no door.

## The Python matrix (ENH-032, D132)

CI's `check` job runs the whole suite on 3.12, 3.13 and 3.14; the tree's development
environment is 3.14 (`.python-version`); `requires-python >= 3.12` is unchanged. The classifiers
say 3.14.

## Behaviour a host may notice

1. **`thread`, `turn` and `mode` are reserved attribute names** (BUG-061). Until 0.34 an attribute
   named `mode` overrode the key the shipped governance selects its policy by — a `read-only`
   thread with `attributes={"mode": "full"}` was judged as `full`. `Thread.open`, `turn` and
   `resume` refuse them by name (`invalid` on the wire), as `posture`, `component` and `inputs`
   were already.
2. **A failed provider turn is `failed`** (BUG-060, above).
3. **`ask` asks before a web read it used to refuse** (D138, above). A host on `ask` sees a new
   kind of question; an `allow` rule answers it standing.

## Nothing else moved

`ModelPort`, `AgentPort`, `Thread`, `Harness`, `run()`, the environment, the leash, the wire's
methods and the schemas' shapes are unchanged beyond the fields above. The two ports stay two —
inference and agency — under one `Thread`; a new invariant refuses a vendor's name in the kernel's
or the runtime's code, so "a provider is a file" (D40) is a test now, not a discipline.

## 0.34.1 — two patches, measured by a product on 0.34.0

- **A fork is a fresh provider session with the transcript** (BUG-062). `Thread.fork` had copied
  the record whole, `session_id` included, so D139's move after `session_gone` resumed the gone
  session again. Now `fork()` and `rollback()` leave `session_id` empty and record
  `seeded_turns`; the first turn on such a record is told the kept turns ahead of its prompt —
  once, by the kit — and then carries the fresh session's own id. `thread/fork` and
  `thread/rollback` on the wire behave the same; their results show `session_id: ""` and
  `seeded_turns`. A host that seeded a rollback's first turn itself should stop, or it will be
  seeded twice.
- **A thread turn's cache tokens reach `Spent`** (BUG-063). The step→meter join dropped the two
  counters, so `Spent.cache_read_tokens` was 0 for every thread while `Usage` carried it. Fixed
  at the join and on every `settle` path; nothing changes in the shapes.
