# 0.42.0 — the loop is visible and steerable

**Nothing to change.** One new component and one method that can now answer `True` where it always
answered `False`. A *Pins* row because the published shape grew (D9); protocol 3 unchanged.

Your asks 8 and 9.

## The agent's own plan

```python
from shadow_hdk.adapters.agent.planning import plan_components, UPDATE_PLAN

plan = plan_components()
# ... register it with the rest; then either:
plan.plan          # the latest, for a host attaching mid-run
# ... or read Invoked events where component == UPDATE_PLAN, for every revision in order
```

You were right that half of this existed and right that it was not the half you needed. `Composed`,
`PlanAdmitted`/`PlanRefused` and `items()` say what the **runtime** is about to do — read those first,
as we suggested. What was missing is the agent's own narration, revised as it learns.

`update_plan(items)` takes `{"step", "status"}` and **declares no effects at all** (D171), so every
mode admits it, `read-only` included. That is not an oversight: an agent that had to ask permission to
say what it intends would stop saying it, and a narration nobody can afford is worse than none.

**`status` is an open string** (D172) — `pending`, `doing`, `done`, `blocked-on-review`, whatever you
use. The same cut `Provider.transport` makes: an enumeration would change the kit's contract every
time you wanted a status we had not thought of, and a plan's vocabulary is yours.

Refused: a step with no words, and a plan over 200 items — that is a data structure, not a plan
anybody follows.

**The mechanism is ours and the content is yours**, which is where we left it last time and where it
stays. Nothing extra was built to get the revisions onto the record: `Invoked.inputs` already carries
them in order, which is the reason this is a component rather than a runtime concept.

## `steer` works for a key-backed model

`ModelAgent.steer` answered `False` and said so honestly. It can now be `True`.

The loop between steps is the kit's own, which is exactly why this was the one place it could be
(D173). A steer is queued and delivered as the person's words **before the next model call** — not
injected into a request already in flight, because that request cannot be changed and pretending
otherwise would make the `bool` a lie.

The contract is unchanged:

| | |
|---|---|
| a turn running, with a step still to come | `True`, and the words are in the next request |
| no turn running, or one already ended | `False` |
| a one-shot CLI dialect | `False`, as before — no open stdin, nothing to steer |

Parity with a subscription CLI, which is what you asked for.

## Not here

- **What a plan's steps mean, or how they render.** Yours.
- **Steering a request mid-flight.** Not possible, and not faked.
