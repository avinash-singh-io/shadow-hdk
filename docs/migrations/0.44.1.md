# 0.44.1 — a restricted database role can open the adapters

**A patch, and it inverts nothing.** If you pass no new argument, this release behaves exactly as
0.44.0 did. Read it anyway if you run PostgreSQL: the behaviour you have today cannot work under a
correct production database role, and this is the release that gives you one that can.

## What was wrong

The PostgreSQL adapters executed their table DDL **when a pool first opened, and again after every
`aclose()`**. A runtime role with no DDL rights — which is what a production application should have —
failed with **SQLSTATE 42501** and could not start. Four adapters, nine tables.

**Provisioning the tables in advance did not help**, and this is the part worth knowing even if you
never hit the bug: `CREATE TABLE IF NOT EXISTS` is **not** DDL-free. PostgreSQL checks the CREATE
privilege on the schema *before* it checks whether the table exists, so the statement fails against a
table that is already there. There is a test in this release that holds that property against a real
server, because it is counter-intuitive enough to be worth measuring rather than asserting.

## What to do

### 1. Run `prepare` from your migration step

```bash
shadow-hdk-prepare "postgresql://owner:...@host/db"
```

or, in Python:

```python
from shadow_hdk.adapters.postgres import prepare
await prepare(url)
```

Under a role that **may** create tables, **before** your application starts. It is idempotent.

Three things about it, each of which someone will otherwise discover the hard way:

- **It is not optional, even on a database you have already provisioned.** It creates one table you
  do not have — `shadow_hdk_schema_version` — and records the schema version in it.
- **Run it on every deploy, unconditionally.** It is cheap, and deciding whether it is needed is
  exactly the judgement that goes wrong.
- **Re-run it after upgrading shadow-hdk _or LangGraph_.** It calls LangGraph's
  `AsyncPostgresSaver.setup()` for you, under your owner role. That function is LangGraph's, so its
  tables change when that library changes and nothing here can know that they did.

### 2. Grant your runtime role exactly what the manifest says

```python
from shadow_hdk.adapters.postgres import runtime_grants
for statement in runtime_grants("my_runtime_role"):
    ...  # run each as the owner
```

Data rather than prose, so your migration owner can apply it instead of transcribing it — and so this
kit's own test grants exactly what it publishes. **`SELECT` only on the version table**: the runtime
reads it to verify the schema and has no business writing it.

### 3. Turn the DDL-free path on

```python
PostgresStore(url, prepared=True)
PostgresThreads(url, prepared=True)
PostgresEffectJournal(url, prepared=True)
await postgres_checkpointer(url, prepared=True)
```

`prepared=True` issues **no DDL at all** — not conditional DDL, for the reason above. Instead it
verifies, with one catalogue query per pool open, and fails named:

- **`SchemaNotPrepared`** — the version table is absent, so `prepare` was never run.
- **`SchemaBehind`** — the recorded version is older than this code expects.

Both at startup, with the command to run in the message, rather than as a confusing failure later on
whichever statement first meets a missing column. A reopen re-verifies, which is a cheap query and no
longer DDL — that reopen path was the half that made this bug survive a first-use fix.

## It is opt-in here, and the default flips in the first 0.45 release

`prepared` defaults to `False` in 0.44.1, so **a patch release does not invert behaviour** for anyone
relying on self-preparation. The default becomes `True` in the first 0.45 release, as a named
behaviour change in that release's notes. If you want the new behaviour now, pass the argument; if you
want to be ready for the flip, pass it now anyway.

## What did not change

- A host passing no argument behaves exactly as 0.44.0 did, and a test pins that.
- SQLite and in-memory stores are untouched.
- No table's columns, names, indexes or meaning change. **`shadow_hdk_versions` is not the new version
  table** — it holds per-collection row versions for the store's optimistic concurrency, and the
  similar names are a trap worth naming.
- No wire change. Protocol 3 unchanged. A *Pins* row because the published surface grew (D9).
