# 0.35.0 — the read-class file tools

**Nothing to change.** Every addition is additive and `read_file` without a range is byte-for-byte
what it was. A *Pins* row because the published shape grew (D9); protocol 3 unchanged.

## What an environment now offers

Three things a governed agent could not do before, and the reason they matter is what a *governed*
agent is: a CLI run under this kit has its own built-ins off, so the environment's operations are
the whole of what it can do. With six of them, a governed Claude Code was weaker than the same CLI
on its own — every search was a `run_shell`, and every look at a large file arrived whole.

- **`glob(pattern, path?, limit?)`** — files by path pattern. `*` matches within one segment, `**`
  across segments, `?` one character. Files only; paths come back relative to the workspace root,
  while the pattern is matched relative to `path`. Sorted.
- **`grep(pattern, path?, glob?, limit?)`** — a regular expression over file contents. Each match is
  `{"path", "line", "text"}` with a 1-based line number. `glob` narrows which files are searched. A
  file that cannot be read (binary, or gone since the walk) is skipped, not fatal. A pattern that is
  not a regular expression is refused, naming it.
- **`read_file(path, offset?, limit?)`** — `offset` is the first line, counting from 1; `limit` is
  how many. Neither given, it is the whole file as a plain string, exactly as before.

## Two behaviours worth relying on

- **A cap is announced.** Under its limit, `glob` returns a plain list and `grep` a plain list of
  matches. Over it, the result is an object instead — `{"paths": [...], "truncated": true,
  "found": N}` for `glob`, `{"matches": [...], "truncated": true}` for `grep`. A model reads "there
  are more" rather than inferring "there are none". Defaults: `GLOB_LIMIT` 1000, `GREP_LIMIT` 200.
- **A range past the end is refused, naming the line count.** `read_file(path, offset=50)` on a
  two-line file is a `Refused`, not an empty string — an empty string reads to a model as an empty
  file, and it stops looking.

## Why they do not ask

`glob` derives from `list` and `grep` from `read`, so their effect profiles carry no writes, no
reach and no cost. **The shipped `ask` mode does not stop a person for a search**, which is the
whole point: a search that asks permission is a search nobody runs. Before this, searching meant
`run_shell`, which `ask` rightly does stop.

## For an environment adapter

**Nothing to implement.** Both are built on `_list` and `_read` in the base class, so a local
directory, a sandbox and a remote root gain them together. An adapter with something faster — a
real `find`, an index — may override `_glob` and `_grep`; none has to. A walk stops at 50,000 files,
and a directory `_list` cannot read is skipped rather than failing the search.
