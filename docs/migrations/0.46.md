# 0.46.0 — plan limits on a stored agent row

One contract addition (H11-C), so a minor and a Pins row under D9. Protocol 3 unchanged.
Publish the independently frozen 0.45.0 checkpoint first; this checkpoint contains C only as its
new item. D and H6–H8 remain for later releases.

An agent row may now set `plan` as an object containing `depth`, `fan_out` and `steps`, each an
optional bound. It is parsed into the existing `PlanLimits` contract. Absent or null defers to
the run's own limits. Invalid contract values refuse the row through the existing loader.

```toml
name = "planner"
system = "Plan the work."
meta_tools = ["compose", "done"]
[plan]
depth = 3
fan_out = 4
steps = 12
```

The existing child-plan admission meets these limits with the host's bounds; a row cannot widen
the host. This is an admission bound on the kit's planner, not a promise to control a CLI's own
private planning loop. Per-step authorization continues to govern effects after admission.

`absorb` and `offload_over` remain unavailable in a row; do not add them by symmetry. No new
kernel type or port was added. D190: a coding tool, a support desk and a research assistant would
each use whole-plan shape limits. The migration table records the generic property for Shadow.
