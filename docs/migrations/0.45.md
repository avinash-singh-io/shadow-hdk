# 0.45.0 — a stored agent binds a procedure

A minor contract addition (D9); protocol 3 unchanged. This is the first release-train checkpoint:
H11-E, alongside phase 66's previously gated H20, H23 and H11-A/B. C, D and H6–H8 remain for
separate releases. `absorb` and `offload_over` are not added to stored rows.

## Named behaviour change: PostgreSQL runtime is DDL-free by default

Run trusted preparation under an owner role before starting the application, and again after every
shadow-hdk or LangGraph upgrade:

```python
from shadow_hdk.adapters.postgres import prepare, runtime_grants
await prepare(owner_url)
for statement in runtime_grants("runtime_role"):
    ...  # apply under the owner role
```

`PostgresStore`, `PostgresThreads`, `PostgresEffectJournal` and `postgres_checkpointer` now default
to `prepared=True`. The stores verify preparation on open and reopen and raise `SchemaNotPrepared`
or `SchemaBehind` when needed. The checkpointer skips LangGraph's `setup()`; trusted preparation
must already have made its tables. Explicit `prepared=False` retains legacy self-preparation under
a role that may create tables. SQLite is unaffected. The schema version remains 1.

## Agent-row skill binding

An agent document may name `skill` beside `name` and `system`. The name resolves in the same host
registry as stored and shipped skills. An unknown skill refuses before opening either provider,
naming the missing entry and the available names. An omitted field remains unbound.

On a key-backed model the procedure is bound to the kit-owned loop. Its needs are checked against
the visible registry before the first model call, and its procedure joins the agent's instructions.
On a CLI or handed agent, `unmapped_behaviour` includes `agent.skill` for the unsupported
**pre-binding**. Skills remain available by choosing through the governed `use_skill` component,
including the needs check (D17, D55). Delivering the procedure text without that check is not binding.
No new decision was needed: this follows the already approved E design.

## Previously gated changes shipping here

- `tools_offered` refuses a name nothing answers to. Audit configured names before pinning; a typo
  formerly had no effect and now refuses the turn.
- Set `model` explicitly on Codex modes. A governed launch uses `--ignore-user-config` when tools
  are injected, so a missing model selects the CLI default rather than a person's configuration.
- `agent_unhonoured` appears on the thread, record and thread-start reply. It names a requested
  agent loop the kit could not run; a product can distinguish this from no agent having been asked
  for. The agent's role and tool list still compose into provider behaviour.
- A host may choose a change-diff cap; a truncated diff can be fetched through the governed
  `change_diff` component while its bounded handle remains held.

D190: a coding tool, a support desk and a research assistant would each use procedure binding,
truthful unsupported-contribution reporting and separation of trusted provisioning from runtime.
