# Migrating from 0.32 to 0.33

Phase 41 — *Linux confinement* (Epic 0010's first phase). A confined mode opens on Linux the way it
opens on macOS: proven, by the operating system's own mechanism, and it keeps opening on the Linux
a laptop actually runs — Ubuntu 24.04, whose default AppArmor policy blocks the unprivileged user
namespace bubblewrap needs. Nothing an existing caller does changes; the protocol stays at `3`.
What changes is *which* mechanism confines a local process on Linux, and that the evidence now says
which.

## What a Linux host sees now

- `pip install shadow-hdk` on Linux x86_64 or aarch64 brings **`shadow-hdk-linux-sandbox`** — a
  small static helper (Rust; Landlock + seccomp applied to itself before `exec`) as a platform
  wheel, versioned in lockstep with the kit. It lands beside the interpreter (`<venv>/bin`), where
  `LocalEnvironment` looks first. Other Linux architectures install nothing extra and keep the
  bubblewrap path.
- `LocalEnvironment.open(root, mode="workspace-write")` tries the machine's mechanisms **in the
  field's order** — the helper (when the kernel has Landlock, 5.13+), then bubblewrap — and the
  D36 proof decides: each candidate is watched denying a write outside the root, refusing a socket
  and allowing a write inside; the first that passes is in force. A candidate that confines nothing
  is passed over. When none passes, `CannotEnforce` names each one tried and what the proof did not
  see; when there is none, it names the three the kit knows and what would install them.
- On macOS nothing changes: seatbelt (`sandbox-exec`), as before.
- **No `sudo`, no sysctl, no daemon** on Ubuntu 24.04 with the helper. The sysctl
  (`kernel.apparmor_restrict_unprivileged_userns=0`) is what the *fallback* needs on a kernel
  without Landlock; the refusal says so when that is the machine.

## `Isolation.mechanism` — the evidence names what confines

`Isolation` gains `mechanism: str` — `"seatbelt"`, `"landlock"`, `"bubblewrap"`, a box backend's
name (`"opensandbox"`), or `""` where nothing was watched. It is on the capability evidence a host
already reads: the `writes` evidence says `landlock confines writes` rather than `isolation
confines writes`; `network` likewise. `Isolation.none()` is unchanged; every other field is
unchanged; a caller constructing `Isolation` by keyword needs nothing new (the field defaults).

```python
env = await LocalEnvironment.open(root, mode="workspace-write")
env.isolation.mechanism  # "landlock" on a Linux laptop, "seatbelt" on macOS
env.capabilities.evidence  # ... CapabilityEvidence(axis="writes", source="landlock confines writes") ...
```

`prove_box(box, mode=…, mechanism=…)` takes the backend's name so a `SandboxEnvironment` reports it
too; `SandboxEnvironment.open` passes `backend.name`.

## The new names

- `local_sandboxes() -> tuple[LocalSandbox, ...]` — the machine's candidates in order (cached for
  the process; a kernel does not change under it). `local_sandbox()` is the first, or `None`, as
  before.
- `LocalSandbox.detail` — what detection learned beyond the binary (the helper's Landlock ABI and
  version).
- `SHADOW_HDK_SANDBOX=landlock|bubblewrap|seatbelt` narrows the candidates to one — for an
  operator on a machine where one mechanism misbehaves, or a CI job proving the fallback. A name the
  kit does not know raises at detection, naming the three it does.
- `SHADOW_HDK_LINUX_SANDBOX=/path/to/shadow-hdk-linux-sandbox` names the helper when it is neither
  beside the interpreter nor on `PATH` (an artifact that carries it elsewhere).

## The helper's contract

`shadow-hdk-linux-sandbox --mode read-only|workspace-write [--root <dir>]... -- <argv>...` confines
the process and execs the command — one process, in the leash's process group, the command's exit
code. `--probe` prints `{"version", "landlock_abi", "supported"}` and exits 0 or **120**. Exit
**120** is the helper's *cannot confine* (no Landlock; stderr says why), **121** usage, **126** /
**127** the command could not run / was not found. The full contract, what is and is not confined,
is `native/sandbox/README.md`. The kit invokes it; a product never needs to.

What it confines, and what it does not, mirrors the macOS profile: reads everywhere; writes beneath
every root of the workspace for `workspace-write` and nowhere for `read-only`; the null, zero,
random and terminal devices writable in both (devices are not files); `socket()` outside
`AF_UNIX` and `io_uring_setup` refused; TCP `bind`/`connect` denied by Landlock too where the ABI
has it. Reads are **not** confined and ambient secrets are **not** denied — the evidence says so,
as it did on macOS, and a host that requires `reads_within="workspace"` is refused honestly.

## CI, and what "supported" means

The kit's own CI now runs the whole suite on Linux **twice** — with the helper in force and with it
set aside on bubblewrap plus the sysctl — and on macOS on seatbelt; the crate's tests watch the
built binary deny and allow on a kernel; the helper's wheels are built on every push. A red runner
blocks a release (Epic 0010, D126). Windows is not yet supported (no leash, no sandbox — Phase 43,
deferred; WSL2 meanwhile).

## Nothing else moved

`Environment`, `Mode`, `requires`, `run_leashed`, the leash's process control, `Harness`, `Thread`,
`run()`, the wire's methods and the TypeScript client are unchanged. The sidecar's default command
in the TypeScript README still needs `uv` on the machine; the pinned per-OS artifact is Phase 42,
optional.
