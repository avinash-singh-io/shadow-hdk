# Migrating from 0.31.0 to 0.32

Phase 44 — *tools as code, from any language*. A host in any language writes its tools as code and
the runtime calls them back **on the thread door**, through the inversion the wire has had since
D21 for `run`/`resume`. Nothing an existing caller does changes; the protocol stays at `3`. Every
addition below is a parameter, a field or a client method.

## The thread door carries the host's components (ENH-030)

- `thread/start {host_components: true}` and `thread/resume {host_components: true}` add the
  calling connection's own component port to that thread's registry. The runtime asks that
  connection `components.registrations` (what is there) and calls `components.invoke` back to act
  — the same two callbacks `run` has always used. The act is judged, admitted and recorded exactly
  as a component in the serving process would be.
- `tools/list` names such a tool with `source: "host"`. The host's registration crosses untouched
  (a host may sign what it registers, and the signature covers provenance).
- A thread outlives a connection. A host that goes away takes its tools with it, by name: the
  registry lists the port unreachable and the tools vanish; an act in flight ends `failed` naming
  tool and host. A new connection's `thread/resume {host_components: true}` brings its own.
- An irreversible tool declared by a host is recorded with posture `observed` — the runtime never
  held its authority boundary (D99–D104, unchanged from `run`).
- In Python, `ServeHost.open` / `resume` accept `peer_components` — **the wire's keyword**, for the
  port the wire hands in; not a way to pass a product's Python objects into the served composition,
  which stays data (see `docs/for-a-product.md` §7).

## The TypeScript client (ENH-031)

- `tool(id, { description, effects, input, output?, name?, labels? }, handler)` builds a
  `Registration` in the published shape; effects use the battery document's vocabulary
  (`reads`/`writes` as lists or `"everything"`, `reaches`, `reversible`, `contained`, `costs`).
- `client.components.serve([...tools])` answers the runtime's two callbacks. A thrown error is
  `failed`; a thrown `Refusal(reason)` is `refused`.
- `thread.start({ host_components: true })`.
- **`thread.resume(id, options)` takes an options object** — `{ plan_limits?, host_components? }`.
  0.31.0 took a bare `PlanLimits` as the second argument; change `resume(id, limits)` to
  `resume(id, { plan_limits: limits })`.
- The client stands on a `Transport`. `new HarnessClient({ address, … })` is unchanged (HTTP);
  `new HarnessClient({ transport })` takes any transport.
- `shadow-hdk-client/node` — `spawnHarness({ command, args, cwd?, env? })` starts the runtime as a
  child process and speaks JSON-RPC over its stdio; `close()` ends it and its tree. **What is
  spawned is a command you name, and today it needs `uv` on the machine** (`uvx --from
  shadow-hdk==0.32.0 shadow-hdk serve harness.toml --stdio`). The pinned, no-prerequisite binary
  per OS is Epic 0010's, Phase 42; when it lands the `command` becomes that binary and nothing
  else changes.

## 0.32.1 — a patch

- **BUG-056** — `set_mode` and `add_root` during a running turn now refuse with the typed
  `TurnRunning` (`turn_running` on the wire, with `thread_id` and `turn_id`) instead of closing
  the provider's session under the turn. The contract is *between turns, or not at all*; a turn
  asked for while a change is reopening the provider waits and runs on the new session. Read
  `Thread.turning` (in process) or catch `turn_running` (on the wire) before offering a mode
  switch mid-stream.

## Fixed

- **BUG-057** — on Python 3.13 and later the confinement proof read a denied write as a write
  (the interpreter echoes `-c` source in a traceback, marker included) and every confined mode
  refused to open. The proof reads its markers from stdout with a zero exit code and nothing else.
  The kit's tree runs on 3.14 with every extra.
- **BUG-058** — a test compared a union type by identity, which 3.14 no longer guarantees.

## Recorded, not fixed

- **TD-013** — the wire's remote port copies a host's irreversible registration with posture
  `observed`; a host that signs its registrations would see them refused as tampered. The
  annotation belongs beside the registration on the registry side. P2.
