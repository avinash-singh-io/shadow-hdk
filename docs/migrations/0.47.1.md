# 0.47.1 — stored mode fragments reach prompt assembly

H6 / BUG-238 repairs the existing context-fragment contract; patch, no Pins row (D9).
Protocol 3 unchanged. Publish the frozen 0.47.0 candidate first.

Mode documents now decode `behaviour.fragments` as typed, ordered fragments. Both file and
store rows use this parser. The existing store/put wire method already transports mode rows;
no new wire method or row field is introduced. The shared prompt assembler keeps each name,
text and optional source. Previously it raised AttributeError on raw dictionaries.

Malformed fragment rows are refused while loading and appear in the store mode source's
problems. An empty fragment list still adds no context. Other mode behaviour is unchanged.
No caller changes are required.

D190: a coding tool, a support desk and a research assistant would each use named context
from mode data. This is adapter decoding, with no tool meaning or policy in core/runtime.
