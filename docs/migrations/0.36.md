# 0.36.0 — a change names a region

**Nothing to change.** Both operations are additions, and every existing one behaves exactly as it
did. A *Pins* row because the published shape grew (D9); protocol 3 unchanged, and no kernel change.

## What an environment now offers

### `edit_file(path, edits[])`

`edits` is a list of `{"old": …, "new": …}`, applied **in order**, **all of them or none**. A later
edit sees the result of an earlier one.

It is refused, and **nothing is written**, when:

- an `old` is **not in the file** — the picture you are working from is out of date; read it again;
- an `old` appears **more than once** — name more of the surrounding text so it matches exactly
  once. There is no `replace_all`: replacing every occurrence is a different act, and one you
  should have to say out loud;
- `edits` is **empty** — that is a whole-file rewrite under another name.

The refusals are the design rather than error handling. A half-applied batch leaves the file in a
state neither the model nor the record describes, which is worse than not editing at all.

### `move_file(from, to)`

Moves or renames. **A destination that already exists is refused**, naming it — a move does not
overwrite. Parent directories are created.

That refusal is what keeps the move honestly `write`-class: nothing is destroyed, so the act is
reversible by moving it back. A clobbering move would be a `delete` wearing a write's profile, and
the content it destroyed would be on no record anywhere.

## How they are governed

Both derive as **`write`**, exactly like `write_file` — same profile, same judgement in every mode,
and both are **withheld in a `read-only` environment** before governance is asked, because a mode
is the environment's own promise and not one it outsources.

## The diff is the call

You do not need to read the disk to show what an edit will do. `old` and `new` are the call's own
inputs, so they arrive on the approval card through `ApprovalRequested.inputs` **before** anyone
approves, and on the record through `Invoked.inputs` after.

## Refused, or Failed?

**Refused is a decision this operation made; Failed is the world saying no.** The destination check
and the match rules are decisions, so they refuse. A missing file, or a path outside the root, is
the filesystem's answer — those fail, which is the vocabulary `read_file` already uses.

## For an environment adapter

**Nothing to implement.** Both are built on `_read`, `_write` and `_delete`. `_move` is an
*overridable* hook with a working base fallback; `LocalEnvironment` overrides it to rename in
place, which makes the move atomic and lets it carry bytes the text round-trip cannot.
